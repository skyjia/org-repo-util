# 审计报告分析技能

## 技能目的

本技能用于分析审计工具生成的 report.json 文件，提供：
- 审计报告解读（执行摘要、问题分类、修复优先级）
- 修复建议生成（针对每个问题的具体修复方法）
- 配置优化建议（分析 .audit-config.yaml 并给出优化建议）
- 对比分析（对比多次审计报告，评估质量趋势）

本技能不调用外部 AI API，而是由 Claude Code 直接读取和分析报告文件。

## 意图识别规则

当用户提及以下关键词或意图时，应触发本技能：

- `分析报告`、`审计结果`、`解读报告`
- `修复建议`、`如何修复`、`怎么解决`
- `配置优化`、`配置建议`
- `对比分析`、`质量趋势`、`问题变化`
- 提及具体的报告路径（如 `reports/augmn/.../report.json`）
- 提及具体的仓库并要求分析（如 `分析 fe-casamiel-admin 的审计结果`）

## 前置条件

使用本技能前，确保已生成审计报告：

```bash
# 生成单个仓库的审计报告
python3 audit/bin/audit repo repos/augmn/<repo-name> --format json

# 或使用 HTML 格式（同时生成 JSON 和 HTML）
python3 audit/bin/audit repo repos/augmn/<repo-name> --format html
```

报告生成位置：`reports/augmn/<repo-name>/<timestamp>/report.json`

快捷访问：`reports/augmn/<repo-name>/latest/report.json`（软链接到最新报告）

## 工作流程

### 1. 审计报告解读

当用户要求解读审计报告时，执行以下步骤：

**步骤 1：读取报告**
- 使用 Read 工具读取 `report.json` 文件
- 如果用户未指定路径，自动查找 `reports/augmn/<repo-name>/latest/report.json`

**步骤 2：分析报告结构**
提取以下信息：
- 仓库基本信息（repo, language, analyzer）
- 扫描统计（files_scanned, issues count, duration）
- 问题列表（issues 数组）

**步骤 3：生成解读报告**
按以下结构输出 Markdown 格式的解读报告：

```markdown
# 审计报告解读：<repo-name>

## 1. 执行摘要

### 关键发现
- 列出 Top 5 最严重的问题
- 每个问题包含：规则名称、严重级别、文件位置、问题描述

### 风险评估
- CRITICAL/HIGH 级别问题数量
- MEDIUM 级别问题数量
- LOW/INFO 级别问题数量
- 整体风险等级：高/中/低

### 代码质量评分
- 基于问题数量和严重程度给出 1-10 分评分
- 说明评分依据

## 2. 问题分类分析

### 安全漏洞
- 数量统计
- 主要类型（如 XSS、SQL 注入、依赖漏洞等）
- 严重程度分布

### 代码质量问题
- 数量统计
- 主要类型（如未使用变量、空指针风险、异常处理不当等）
- 按规则分布

### 性能问题
- 数量统计（如有）
- 主要类型（如内存泄漏、慢查询等）

### 代码风格问题
- 数量统计
- 主要类型（如命名规范、格式化等）

## 3. 修复优先级建议

### 必须立即修复（CRITICAL/HIGH）
- 列出所有 HIGH 和 CRITICAL 级别问题
- 说明为什么需要立即修复
- 预估工作量

### 建议尽快修复（MEDIUM）
- 列出 MEDIUM 级别问题
- 说明影响
- 预估工作量

### 可以延后处理（LOW/INFO）
- 列出 LOW 和 INFO 级别问题
- 说明为什么可以延后

## 4. 关键问题详解

针对 Top 5 最严重的问题，逐一详细说明：

### 问题 1：<规则名称>
- **位置**：<文件路径>:<行号>
- **严重级别**：<CRITICAL/HIGH/MEDIUM/LOW/INFO>
- **问题描述**：<详细说明>
- **问题原因**：<为什么会出现这个问题>
- **潜在影响**：<可能导致什么后果>
- **修复方法**：<具体的修复步骤和代码示例>

（重复 5 次）

## 5. 总体建议

### 代码质量改进方向
- 针对主要问题类型给出改进建议
- 推荐的编码实践

### 安全加固建议
- 安全相关问题的修复优先级
- 安全编码最佳实践

### 最佳实践推荐
- 代码审查流程建议
- 自动化检查建议
- 持续改进建议
```

**步骤 4：保存报告（可选）**
- 如果用户要求保存，将解读报告保存为 `ai-interpretation.md`
- 保存位置：与 report.json 同目录

---

### 2. 修复建议生成

当用户要求生成修复建议时，执行以下步骤：

**步骤 1：读取报告**
- 读取 `report.json` 文件
- 提取所有问题列表

**步骤 2：按严重程度排序**
- 按 CRITICAL > HIGH > MEDIUM > LOW > INFO 排序
- 选取 Top N 个问题（默认 10，用户可指定）

**步骤 3：生成修复建议**
对每个问题生成详细的修复建议：

```markdown
# 修复建议：<repo-name>

## 问题 1：<规则名称>

### 问题信息
- **文件**：<文件路径>:<行号>
- **严重级别**：<级别>
- **问题描述**：<描述>

### 修复方法

**修改前：**
```<language>
<原始代码>
```

**修改后：**
```<language>
<修复后的代码>
```

### 修复说明
- 详细说明修复的原因和方法
- 注意事项

---

（重复 N 次）

## 批量修复建议

### 同类问题
- 哪些问题是同一类型，可以批量修复
- 推荐的修复顺序

### 工作量评估
- 总问题数
- 预估修复时间
- 优先级建议
```

**步骤 4：保存报告（可选）**
- 保存为 `ai-fix-suggestions.md`
- 保存位置：与 report.json 同目录

---

### 3. 配置优化建议

当用户要求优化审计配置时，执行以下步骤：

**步骤 1：读取配置文件**
- 读取 `repos/augmn/<repo-name>/.audit-config.yaml`
- 如果不存在，说明当前使用默认配置

**步骤 2：分析仓库结构**
- 检测项目类型（前端/后端/全栈）
- 检测使用的框架和工具
- 检测现有的代码风格配置

**步骤 3：生成优化建议**

```markdown
# 配置优化建议：<repo-name>

## 1. 当前配置评估

### 配置概览
- 启用的分析器
- 启用的规则集
- 排除的文件/目录

### 合理性评估
- 配置是否匹配项目类型
- 是否有遗漏的检查项
- 是否有不必要的检查

## 2. 规则优化建议

### 建议启用的规则
- 规则名称
- 启用原因
- 预期效果

### 建议禁用的规则
- 规则名称
- 禁用原因
- 影响评估

### 严重级别调整
- 哪些规则需要调整级别
- 调整原因

## 3. 排除项优化

### 建议排除的路径/文件
- 路径/文件模式
- 排除原因

### 建议取消排除的路径/文件
- 路径/文件模式
- 取消原因

## 4. 建议的配置变更

### YAML 配置示例
```yaml
<具体的配置修改建议>
```

### 变更说明
- 每项修改的原因
- 预期效果
```

### 4. 对比分析

当用户要求对比多次审计报告时，执行以下步骤：

**步骤 1：读取两份报告**
- 读取基线报告 report1.json
- 读取最新报告 report2.json

**步骤 2：提取问题列表**
- 从两份报告中提取所有问题
- 按文件+行号+规则生成问题唯一标识

**步骤 3：对比分析**

```markdown
# 审计报告对比分析：<repo-name>

## 1. 问题数量变化

### 总体统计
- 基线报告问题数：<N1>
- 最新报告问题数：<N2>
- 变化：<增加/减少> <数量>

### 新增问题
- 数量：<N>
- 列表（Top 10）：
  - <规则>: <文件>:<行号>

### 已修复问题
- 数量：<N>
- 列表（Top 10）：
  - <规则>: <文件>:<行号>

### 持续存在的问题
- 数量：<N>
- 列表（Top 10）：
  - <规则>: <文件>:<行号>

## 2. 质量趋势

### 按严重级别分析
- CRITICAL: <基线> → <最新> (变化)
- HIGH: <基线> → <最新> (变化)
- MEDIUM: <基线> → <最新> (变化)
- LOW: <基线> → <最新> (变化)

### 按类别分析
- 安全问题: <基线> → <最新> (变化)
- 质量问题: <基线> → <最新> (变化)
- 性能问题: <基线> → <最新> (变化)
- 风格问题: <基线> → <最新> (变化)

### 整体趋势
- 代码质量是提升还是下降
- 改善最多的类别
- 恶化最多的类别

## 3. 修复效果评估

### 有效修复
- 哪些问题已成功修复
- 修复方法是否恰当

### 未解决问题
- 哪些问题一直存在
- 为什么难以修复

### 新引入问题
- 是否引入了新问题
- 可能的原因

## 4. 下一步建议

### 优先处理的问题
- 持续存在的高严重级别问题
- 新引入的严重问题

### 需要关注的趋势
- 恶化的问题类别
- 需要加强的方面

### 改进建议
- 具体的改进行动
- 预期效果
```

## 输出规范

1. **格式**：所有报告使用 Markdown 格式
2. **语言**：使用中文，技术术语保留英文
3. **结构**：严格按照上述模板结构输出
4. **代码示例**：提供修改前后的对比代码（如适用）
5. **可操作性**：建议必须具体、可执行

## 注意事项

1. **不要调用外部 API**：本技能由 Claude Code 直接分析，不调用 anthropic/openai API
2. **不要生成命令**：不需要将分析功能封装成 CLI 命令
3. **读取最新报告**：如果用户未指定报告路径，自动使用 `latest` 软链接
4. **保存位置**：AI 生成的报告保存在与 report.json 同目录下
5. **项目特定**：本技能仅适用于当前项目的审计工具，不是通用技能
